Machine-Learning-Based Content Prioritization for Search Visibility Review

Using observed search visibility, content age, position, and engagement signals to help prioritize content pages for human review.

FlyRank ML Internship Dataset Ranking / Scoring Random Forest Grouped-by-Client Validation
01 — Abstract

Research at a glance

This study asks whether a machine-learning ranking/scoring approach can help prioritize content pages for human review using observed search visibility, content age, position, and engagement signals. Using an anonymized working sample of 30,000 content observations from the FlyRank ML Internship dataset, the analysis defines a binary target for observed downward trend and evaluates a Random Forest model against a Week-4 baseline using a grouped-by-client validation split.

On the evaluated split, the Random Forest achieved a measured F1 score of 0.6343, while the Week-4 baseline achieved 0.6812. The baseline therefore performed better on this particular evaluation. The model and observed content signals were then used as evidence layers for a ranked decision-support queue with human-readable reason codes.

These results are directional evidence from the evaluated sample and should not be interpreted as causal proof that a recommended content action will improve search performance.

02 — Introduction

The decision this work supports

Content and SEO teams may need to review a large number of pages while having limited editorial time. The practical question is not simply whether a page is performing well or poorly, but which pages should receive human attention first.

This project frames that problem as a ranking and scoring task. The goal is to turn observed content and search signals into a prioritized review queue.

The output is intended as decision-support for editors and SEO/content teams. It is not an automatic prediction that a page will decline, and it does not claim that a recommended action will improve performance.

DECISION

What to review first?

Prioritize content pages for human review when editorial resources are limited.

INPUT

03 — Data

Dataset and working sample

This project uses the FlyRank ML Internship dataset provided for the internship track. The working dataset contains anonymized content-level observations.

The evaluated working sample contains 30,000 rows, 44 columns, and 32 clients. The analysis focuses on public-safe aggregate signals such as search volume, competition, impressions, clicks, pageviews, sessions, content age, freshness, search position, and engagement-related measures.

The modeling target is derived from trend_direction. A value of down is represented as 1, while up and stable are represented as 0.

Target distribution

The evaluated dataset contains 16,262 observations in the downward-trend class and 13,738 observations in the non-downward class.

This corresponds to approximately 54.21% down and 45.79% non-down.

Excluded from model features

Identifier fields such as client_id and content_id were not used as model features. Target-related fields such as trend_direction, trend_pct, and the derived target_down label were also excluded from the model feature set to reduce direct target leakage.

04 — Methodology

From observed signals to model evaluation

The task is framed as a ranking/scoring problem for content prioritization. The model predicts whether the observed trend direction is down.

The binary target is defined as 1 when trend_direction = down and 0 when trend_direction = up or stable.

A Random Forest classifier was used as the Week-5 model. The Week-4 baseline provides the comparison point.

The model uses 34 content and performance features covering search demand, competition, content length, impressions, clicks, pageviews, sessions, users, engagement signals, content age, freshness, search position, and categorical content attributes.

Validation uses a grouped-by-client split so that content from the same client does not appear in both training and test data. The evaluated split contained 24 training clients and 8 test clients, with zero client overlap.

The split contained 22,885 training rows and 7,115 test rows.

A feature-level leakage audit found no target-related columns or identifier columns in the final feature list. This reduces the risk of direct leakage, but it does not prove that every feature is temporally independent of the target.

The model is therefore interpreted as decision-support evidence for prioritization rather than as a causal model or a guarantee of future content performance.

05 — Results

Model versus baseline

On the evaluated grouped-by-client split, the Week-5 Random Forest produced a measured F1 score of 0.6343.

The Week-4 baseline produced a measured F1 score of 0.6812 on the same evaluation framing.

Therefore, the Random Forest did not outperform the baseline in this evaluation. The baseline exceeded the Random Forest by approximately 0.0469 F1 points.

This is an observed result on the evaluated data. It should not be interpreted as evidence that the baseline or Random Forest will perform the same way on all future clients or datasets.

06 — Ranked Recommendations

An editorial action playbook

The action playbook converts observed content signals into a ranked decision-support queue for editors and SEO/content teams.

The final queue contains 30,000 items.

The generated recommendation-distribution figure below shows the current distribution of the five reason codes in the evaluated queue. The exact category counts are preserved in the generated recommendation_summary.csv artifact.

01

STALE_HIGH_VOLUME

Review older content with substantial observed search visibility. Consider whether information is outdated or whether a refresh is justified.

02

THIN_VISIBLE

Review content with relatively limited content depth and existing visibility for useful expansion, missing subtopics, examples, and definitions.

03

POSITION_OPPORTUNITY

Review search intent, completeness, internal links, and page structure where observed average position suggests a potential review opportunity.

04

REFRESH_REVIEW

Review freshness, potentially outdated information, and whether a content refresh is warranted.

05

MONITOR

Monitor performance before taking action when current evidence is not strong enough to justify immediate review.

Model + Playbook Relationship

How the two layers work together

1. Random Forest

Provides a model-based signal for whether a content item is associated with the observed downward-trend class.

2. Action Playbook

Uses observed content signals such as freshness, impressions, word count, and average position to assign human-readable reason codes.

3. Human Review

Editors consider the model evidence and content signals together with page context, search intent, and business importance before taking action.

Important distinction
  • The Random Forest is the model-evidence layer.
  • The action playbook is the operational prioritization layer.
  • The Random Forest does not automatically determine the recommended action.
  • Final content decisions remain subject to human review.
07 — Limitations & Honest Framing

What this study cannot claim

This study provides measured, directional evidence for content prioritization, but it does not establish that the model will generalize to every client or future search environment.

The model predicts whether a content item is associated with a downward trend based on the available features and historical data. It does not prove that a recommended refresh will cause traffic or rankings to improve.

The grouped-by-client validation reduces the risk of evaluating on clients seen during training, but the evaluation uses one grouped split and should not be treated as a guarantee of future performance.

The leakage audit found no direct target-related or identifier columns in the final feature set, but this does not prove that every feature is temporally independent of the target.

Honest framing
  • The measured Random Forest F1 was 0.6343.
  • The measured Week-4 baseline F1 was 0.6812.
  • The baseline therefore outperformed the Random Forest in this evaluation.
  • Results are observed on one grouped-by-client evaluation split.
  • Results are directional evidence, not causal evidence.
  • The output is decision-support, not automatic decision-making.
  • Human review remains required before content changes.
  • The model should not be described as revealing Google's ranking algorithm or ranking factors.
